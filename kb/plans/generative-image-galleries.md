# Generative image galleries

## Overview

When a generation request leaves visual alternatives open, a single paid image
forces the agent to pick blind or serially re-prompt. This feature makes the
candidate-review loop a first-class primitive:

- **Portable gallery** (`slopcamera.image.gallery`, `slopcamera image
  gallery`, MCP `execute_slopcamera`): plan bounded candidates — repeated
  counts, `--vary` axes (style/palette/material/lighting/mood/detail with
  kind-aware defaults), or an explicit `{id, prompt|variant}` list — generate
  them with bounded parallelism (4 in flight), and composite a labelled
  `gallery.png` plus a provenance `receipt.json` (per-candidate path, SHA-256,
  request ID, cell geometry, `clientMaxRetries: 0`).
- **Durable desktop lane** (`slopcamera ai image gallery`): the same planner
  and compositor, but each candidate is one tracked Gateway job
  (`createGatewayJobTracker` + `executeTrackedGatewayOperation`) whose bytes
  publish through the generated-artifact store. The receipt keeps each
  candidate's durable path and job record; ambiguous paid attempts stay
  reconcilable.
- **Scene consumption**: additive v1 contract surface — `material.map` on
  authored procedural mesh materials and a `kind: "environment"` entity
  (equirect image asset driving background, IBL, or both with bounded
  intensity) — plus `set-material` patch op, lowering/prep in the Three
  runtime, and audit/inspect coverage.
- **Agent ergonomics**: `skills/slopcamera/references/image-galleries.md`
  documents review → explicit promotion; `gateway-media.md`,
  `directed-scenes.md`, `docs/how-to/generate-media.md`, and
  `docs/spatial-scenes.md` cross-link it.

## Constraints

- One paid call per candidate, `maxRetries: 0`, never resubmit an ambiguous
  attempt; failed candidates stay in the sheet labelled `failed` with their
  job records retained.
- No-replace publication: existing `gallery.png`/`receipt.json` conflicts
  before any paid dispatch; generated bytes never overwrite authored source.
- Promotion is explicit: gallery output never applies itself to a scene,
  project, or design slot.
- Bounded everything: ≤16 candidates, prompt/variant/cell/pixel limits,
  candidates JSON read from a bounded local file.
- Kind contracts lock the useful frame: `texture` tiles, `skybox` is a 2:1
  equirect with centered horizon, `backdrop` is a 16:9 plate, `sprite`
  isolates one subject, `image` is the generic 1:1 contract.
- A frame renders at most one visible environment entity — alternates gate
  through authored `visible` flags rather than silent first-wins.
- Material maps apply to authored procedural geometry only; source-material
  GLB meshes reject `set-material`.
- Generator modules still reject asset references; a selected texture enters
  as an authored `add-asset` + `set-material`/`add-entity` patch.

## Work

1. `src/image-gallery.ts` — planner (`planSlopcameraGallery`), shared `--vary`
   parser (`parseSlopcameraGalleryVary`), bounded generation
   (`generateSlopcameraImageGallery`), and the composition seam
   (`composeSlopcameraImageGallery`) that accepts in-memory or pre-published
   candidates (`path`/`sha256`/`job`), validates digests, and preserves
   durable references.
2. Registry/MCP/CLI — `slopcamera.image.gallery` operation, MCP confinement,
   headless `slopcamera image gallery`, desktop portable-surface delegation.
3. Scene contract — `map` on unlit/standard materials, `environment` entity,
   `set-material` op, identity/reference validation, inspect/audit/evaluate
   coverage; lowering binds `THREE.Texture` maps and equirect
   `scene.background`/`scene.environment` (rotation + intensity).
4. Desktop `ai` lane — `ai image gallery` args/help/host-resource claims,
   per-candidate tracked jobs through `mapBounded`, durable artifact
   publication, JSON/human summary.
5. Docs and agent skill — new `image-galleries.md` reference, SKILL.md row,
   gateway-media/directed-scenes cross-links, generate-media how-to section,
   spatial-scenes profile table.
