Why install it

Your agent reuses the pipeline instead of writing it.

A one-shot reply carries the scene, the renderer, the export code, and the checks, and the next request writes them again. With Slopcamera installed, that work already exists.

  1. Write a short source, not a pipeline

    The agent writes diagram JSON, scene JSON, an HTML scaffold, or Blender, CadQuery, or Manim source. The CLI renders it and writes the variants each technique supports, such as light and dark diagrams or 16:9 and 9:16 cuts of a video.

    See the techniques

  2. Check before you render

    A strict check names labels that overflow their boxes, shapes outside the canvas, and arrows too short to read. Scene checks validate the scene file, and scene audits sample what a named camera sees over time. The agent fixes the source before it renders.

    Check a first diagram

  3. Revise by editing, then render again

    The source stays beside every output. A change is an edit to that file and one command:

    - "label": "Delivery",
+ "label": "Social delivery",

slopcamera diagram render \
  source-to-film.diagram.json
    See the revised render

How it works

From a short source to every format.

You describe the result. Your agent writes the source files, renders them on your machine, and keeps them for the next change.

  1. 1
    Prepare the sources

    Tell your agent what you have, or start from scratch. It checks which tools your machine has.

  2. 2
    Direct the result

    Say what should change and what must stay the same. Your agent can also generate images, video, and voice through your Vercel AI Gateway account.

  3. 3
    Compose the film

    Rendered shots, generated media, and your footage land in one project with captions, graphics, color, and sound.

  4. 4
    Review before final

    Look at the same frames your agent sees. Preview and final renders use the same timeline and composition.

  5. 5
    Deliver and revise

    Export 16:9, 9:16, 1:1, and 4:5 cuts, clean or captioned, from one edit. Sources stay editable, so a later change is a small edit.

Your files

What stays on your machine

Slopcamera keeps editable source beside each render. Sources, edits, and local renders stay on your own storage; generation and selected cloud analysis use the services described below.

Source media stays unchanged
Original recordings and imported media stay unchanged. Cuts, framing, overlays, and effects remain project decisions.
Project state stays on your machine
There is no Slopcamera account or hosted project database. You control source, project state, previews, and final files.
Gateway credentials stay local
Local processes use your Vercel AI Gateway credential without storing or printing it. Media uploads require acknowledgement.
Operations leave a record
Important operations save a record of their inputs and outputs, with no secrets in it.

Native engine jobs run only with --allow-trusted-code. They and custom Bun workflows run as your current user, without an operating-system sandbox, so review their source first. Read the security policy and privacy guide.

FAQ

Common questions

Why not just ask the agent directly?

You can, and for one throwaway image that is often enough. Each retry writes the take again, with new timing and framing. Slopcamera keeps the source beside the render, so your agent changes one field and renders again. When each approach fits.

How is Slopcamera different from Remotion or HyperFrames?

Remotion renders React components to video, and HyperFrames renders HTML to video. Both offer cloud rendering and have larger communities. Slopcamera renders HTML motion too, and adds diagrams, Three.js scenes, Blender, CadQuery, and Manim films, and edits of your own footage, in one local project. See how they compare, or read Slopcamera vs Remotion, Slopcamera vs HyperFrames, and Remotion alternatives for coding agents.

Do I need to write code?

No. Describe the result; your agent writes and runs the commands. The CLI, SDK, and MCP stay for people who want them.

Does Slopcamera require an account or subscription?

No. Slopcamera has no account or subscription. Generation uses your own Vercel AI Gateway account, or prepaid Hraness Credits for hosted image generation.

What does it cost?

Slopcamera is free; editing, diagrams, vectorization, and exports run locally. Model usage is billed to your Vercel AI Gateway account, or to prepaid Hraness Credits for hosted image generation.

Where do my Gateway credentials live?

In the local CLI or SDK environment; never stored or sent to this website. vercel env run -- <command> injects it for one command.

Which platforms does Slopcamera run on?

The CLI needs Bun 1.3.14+ on macOS, Linux, or Windows, and imports existing recording bundles; it does not start a new screen or camera recording. slopcamera doctor and the capability reference name the rest.

Does Slopcamera overwrite original media?

Edits leave original recordings and imported media unchanged. Diagram renders replace only their named derived outputs.

When can local media leave the machine?

Editing and rendering stay local. Gateway generation and selected cloud analysis upload named media only after acknowledgement. Native Python and custom Bun workflows run with current-user access, including possible network access.

Which agents can use the skill, and how do I install it for Claude Code?

Codex, Claude Code, and agents that read ~/.agents/skills. After the CLI, slopcamera skill install sets it up for Codex, --target agents for other agents that read ~/.agents/skills, and --target claude for Claude Code. Add --scope project for one repository.

Does the Slopcamera website generate or edit media?

No. This website has no upload or generation features. Media work runs in the Slopcamera CLI and SDK; MCP exposes a documented subset.

Is Slopcamera the same as Atet?

Yes. Atet was renamed Slopcamera in September 2026, and atet.sh now redirects here. Old Atet releases still install Atet, not Slopcamera.
